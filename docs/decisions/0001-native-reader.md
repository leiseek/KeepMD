**决策 0001：原生阅读核心、软件绘制默认、独立图表模块**

日期：2026-10-02。状态：P0 初步验证后采用；发布前继续复测。

KeepMD 使用 C++20、Win32、DirectWrite、Direct2D、WIC 和固定提交 MD4C。Tinta 仅提取纯 C++ flowchart 解析/布局，原文件保持未改，其他阅读与资源代码由 KeepMD 管理。

在本机 S100 语料的 30 次新进程、温热缓存测量中，软件绘制的内部首屏 p95 为 75.42 ms，Private Bytes 中位数 20.77 MiB；硬件绘制对应约 205.68 ms、63.88 MiB。当前选择软件绘制作为默认，`KEEPMD_RENDERER=hardware` 保留为开发和基准选项。此结论只代表当前机器和语料，不概括所有 GPU、DPI 或复杂文档。

基准文件：`bench/results/software-s100-p0.json`、`hardware-s100-p0.json`。最早一轮硬件测量与参考程序编译重叠，已保存为 `hardware-s100-contended.json`，不用于决策。此前隐藏窗口的首次 smoke 报告同样不用于启动结论。后续计时已加入跨进程 QPC，以补充包含进程创建的完整启动口径。

Tinta 参考使用原样 Release x64 源码、独立便携配置，关闭更新检查和首次文件关联提示。单轮探索中 S100 私有内存约 186 MiB；L10 触发 512 MiB 停止阈值，采样时已到约 743 MiB。最初没有进程停止阈值的 L10 探索曾增长到超过 10 GiB，已手动终止并排除正常排名。这些结果只说明该固定版本与测试语料组合存在待解释资源行为，不是所有文档/版本的结论；参考程序首屏未测，不比较启动速度。证据见 `bench/results/tinta-reference.json`。

KeepMD 原始超长段落样例曾需要约 4.94 秒排版。采用最多约 8192 UTF-16 单元的物理分片、保留语义文本连续性后，三次初测内部首屏中位数约 76 ms。复制和跨分片查找回归通过。此改动可能在极长段落分片边界提前换行；正常段落不受影响。后续需要扩大 Unicode 组合字符、超长代码行与表格单元格的边界测试。

资源策略：文档语义可随文件大小增长；昂贵布局有缓存上限，图片布局仅存块身份，位图由单一资源表持有，当前图片/图表资源目标 24 MiB。工作队列长度有界，旧文档结果按版本丢弃。该策略还需压力测试验证在途结果与实际驻留峰值。

后续已完成流程图矩阵、资源压力与启动口径验证，并交付按需源码编辑；最终结果以交付验证报告为准，本文件保留 P0 决策时的数据。
